# dsh-mobile-maxxing v1.0.3 リリースノート

公開日: 2026-11-06

実機から届いた2件の報告（ハンバーガーメニューが押せない／Web UI からの更新が失敗する）への修正リリースです。

## 主な変更

### ハンバーガーメニューが反応しない（iOS / Android 共通）

ハンバーガー（FAB）は画面左端 x=8〜48、中心が x=28 にあります。iOS の端スワイプ対策として左端 28px 以内のタッチを `touchstart` で打ち消していたため、**合成クリックが出ず**「押しても何も起きない」状態でした（右半分を押すと反応するので「反応が悪い」に見えていました）。

- ハンバーガーは**クリックではなく touchend で動作**するようにしました（指の移動が 10px 未満ならタップ）。端スワイプ処理にクリックを消されても関係なく動きます
- マウス・キーボード用に `click` も残し、二重実行しないよう 500ms ガード

### Web UI からの更新が失敗する（`spawn dsh ENOENT`）

更新処理が `dsh` コマンドを PATH から探して実行していたため、サーバーの起動方法によっては必ず失敗していました（systemd の最小 PATH、Docker、launchd、Windows の `dsh.cmd` など）。

- **いま動いている CLI をそのまま使う**ようにしました（同じ Node + そのプロセスの `bin.js`）。PATH に依存しません
- インストール元を `github:` から**リリースの tarball URL** に変更（git のインストールや clone 可能なネットワークが不要）
- `--force` を付けて再インストールを確実にし、タイムアウトを 180 秒に延長、**一時的なネットワーク失敗は1回だけ自動再試行**
- 同時実行を防ぐガードを追加（実行中は 409 と「別の更新が実行中です」）

### 失敗理由をわかりやすく表示

生の `spawn dsh ENOENT` ではなく、**理由と対処**を日本語・英語で表示します。技術的な出力は「技術的な詳細」に折りたたみます。

| コード | 表示する理由 | 対処 |
| --- | --- | --- |
| `cli-missing` | サーバーで dsh コマンドが見つかりませんでした | PATH に入れて起動し直す／`npm i -g @deepseek-ai/dsh` |
| `network` | サーバーから GitHub に接続できませんでした | ネットワーク・プロキシを確認 |
| `timeout` | 更新が時間内に終わりませんでした | 再試行 |
| `release-missing` | リリースのファイルをダウンロードできませんでした | 時間をおいて再試行／コマンドライン |
| `permission` | プロファイルに書き込めませんでした | DSH ホームの権限を確認 |
| `disk` | 空き容量が足りません | 容量を確保 |
| `busy` | 別の更新が実行中です | 完了を待つ |

## 検証

- テスト: **780 / 766 pass / 0 fail**、日本語化 41/41
- 追加: 失敗の分類（CLI 不在・ネットワーク・404・権限・容量・不明）と、ルートが `code / hint / detail` を返すことの回帰テスト

## 既知の制限

- 更新はサーバー上で実行されるため、サーバーが GitHub に到達できない環境では失敗します（その場合は上記の理由が表示されます）。
