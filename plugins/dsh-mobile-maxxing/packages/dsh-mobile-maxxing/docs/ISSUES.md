# Known issues

## 修正済み: #75 Trajectory タブをスマホで隠して到達不能にしていた

- 2026-10-27
- 原因: 75e1ca0 はスマホで Trajectory タブを CSS で `display: none` にしていた。上流は「…」に畳むタブを **React 側の View 一覧**から決めるので、CSS で隠したタブは「表示中」のまま扱われ、メニューにも入らない。実測（実 GUI 390px, iPhone UA）: タブ列の DOM には チャット + 軌跡 があり、軌跡が `display: none` かつ `data-rdsh-trajectory-tab-hidden`、「…」の中身は ダッシュボード / Browse other plugins / Create your plugin のみ。タブ列の 2 枠目を不可視タブが占有し、どこからも開けなかった。
- 修正: タブを隠すのをやめた（隠す属性・CSS・ラベル照合・スロット読み取りを削除）。上流は幅で畳む（`max(1, floor((行幅-48)/120))`）ので、幅が足りる端末ではタブとして 1 タップ、足りない端末では「…」の先頭項目として出る。実測 390px: チャット / 軌跡 / …（1 行、折り返しなし）、320px: チャット / … で「…」の 1 行目が 軌跡。タップで軌跡ビューが開くことを確認（閲覧のみ）。
- 「…」に自前の項目を足す案は採らなかった。実測でその行は上流メニューのフォーカス集合に入らず（メニューを開いて ArrowDown しても ダッシュボード に移り、軌跡は飛ばされる）、ポインタ専用になってキーボード要件を満たさないため。
- 検証: 実 GUI（3080）を専用 headless Chrome（独自 port / user-data-dir、iPhone UA）で開き、配信バンドルの dsh-mobile-maxxing ブロックだけを作業ツリーの client.js に差し替えて確認した（profile は変更していない）。スクショは docs/verification-20261027/75-*.png。
- 残制限: 実機 iOS / Android は未確認。上流がタブ列の畳み方を変えると、この修正の前提（幅で畳む＝隠さなくてよい）が崩れる。320px 級では軌跡が「…」の中なので 2 タップになる。

## 修正済み: #82 ヘッダーのサブエージェント／ターミナル一覧の見出しと並べ替え

- 2026-10-27
- ヘッダーの件数チップをタップして開く一覧の**上**に種類名を出す（サブエージェント／ターミナル）。表示言語に追従し、ja は「サブエージェント」「ターミナル」。右パネルのタブ上には見出しを追加しない（利用者の確認を受け撤去）。
- サブエージェント一覧の見出し行に「実行中を上に」の1タップ切替を追加。既定は上流の並びのままで、切替は端末ローカル（`localStorage` の `dsh-mobile-maxxing:activity-sort`）に保存し、リロード／再表示でも復元する。
- 並べ替えは行ノード自体を移動する（安定な分割: 実行中を先頭、各グループ内は上流順）。視覚順とキーボード／読み上げ順が一致し、CSS の `order` は使わない。切替を戻すと、ソート開始時の上流順を復元する。React の再描画で戻された場合は次のパスで再適用する（実 GUI で毎秒の再描画を跨いで維持を確認）。
- 実行中かどうかは行の glyph の `data-state="ongoing"` で判定し、翻訳される aria-label には依存しない。開いている一覧は、チップを持つ body 子（アプリ本体）を除いたポータルの中から、チップの種類に対応する形（state glyph を持つ tree、または state glyph を持つ行を含む menu surface）でのみ認識する。アプリ内の検索結果 tree や設定メニューは対象外。ターミナル一覧の「実行中」「終了 10件」のセクション見出しは state glyph を持たないラベルとして読み飛ばす。
- 並べ替え中に上流が行を追加・削除しても、控えている上流順を追随させる（追加行は次の保存済み兄弟をアンカーに挿入し、無ければ末尾。前の兄弟をアンカーにすると、ソートで下がった行の前に入って復元順が壊れる。削除行は詰める）。ソート中の表示は保存済み上流順の安定な分割なので、状態が変わった行もグループ内では上流順に並ぶ。フォーカス中の行が移動で `<body>` に落ちた場合は同じ行へ戻す。teardown／HMR／dispose では見出し・マーカー・並べ替えを元に戻して状態を捨てる。ターミナルは全ジョブ終了・セクション折り畳みで行が無くても見出しを出す。
- `localStorage` が拒否される環境（プライベートモード等）では、そのページ内だけ選択を保持してトグルは動き続ける（次回リロードで保存はされない）。
- 残制限: デスクトップは `phone()` ガードと CSS_PHONE で完全な no-op（見出しも保存値の読み出しもしない）。検証は実 GUI（390x844@3x）で行ったが、セッション名を含むスクリーンショットと実測 JSON はプライバシーのためコミットしていない。

## #80 翻訳パイプライン（翻訳は完了、本番profile導入・実機は未確認）

- 2026-10-26
- モバイルパッケージは `ja` の `addLanguage` / `register` と `__RDSH_PWA_LOCALES__` の注入を持たない。`COPY.ja` はこのパッケージ自身の UI 文言（manifest・SW・通知など）専用で、共有ロケールの辞書ではない。端末の「表示言語」は共有ロケールサービスに登録済みの言語だけを出し、PC は何も変えない。
- `dsh-locale-ja` が `ja` の言語・名前空間の唯一の所有者である。モバイルの tarball には含まれず、依存にも bundle にも入らず、自動で有効化されない。別途ローカルの tarball から入れた場合だけ `ja` が増える。両方を入れても二重登録は起きない。共有の表示言語は書き換えず、この端末だけの投影に留める。
- 翻訳は完了している。64 名前空間 / 2906 キーのすべてにレビュー済みの日本語値があり、英語フォールバックは 0（`translation-status.json` は `complete`）。移行済みの 83 値（`common` 41、`settings` 41、`settings.locale` 1）はそのまま維持し、残りの 2823 キーは 94 バッチに分けて独立レビューしたうえでマージした。数値の正は `packages/dsh-locale-ja/locale/translation-status.json` である。
- モバイル側の ja 表示は実辞書で回帰固定している。idle のサブエージェント件数は名詞先（「サブエージェント 3 件」）、phone で隠すコントロールと分割（「分割」）はコミット済み ja 名前空間のラベルで照合し、デスクトップでは hide が no-op であることもテストで固定する。
- profile 順で `dsh-locale-ja` が後から有効になっても、`locale/change` に加えて公開 `localeService.subscribe()` の store の再publish で追従する。カタログ・端末の選択意思・dispose を保全し、取り下げは System へ戻して再追加で再適用、dispose は最新の Host 表示だけを復元する（外部で取り下げた `ja` を復活させない）。
- Host がこの端末の投影言語へ通知なしに切り替わると `LocaleRuntime.adopt` はイベントを出さない。復元は DSH 0.2.1-rc.2 の `resolveActive()`（runtime-callable だが d.ts では private）を読み取り専用で参照する。この関数が不在・throw・未登録 ID を返す場合は最後に publish された baseline に fallback するため、無通知の変化は検知できない。`write`/`setLocale` は呼ばず、将来の SDK がこの内部 API を保証する前提も置かない。
- 投影 revision は Host の数値（125）のまま `Object(125)` の identity token として公開し、revision の同一性で再描画する mounted text/slot cache を更新する。`<=`・`+ 1`・JSON は数値と同じで、System/dispose では primitive な Host snapshot に戻す。SDK の public 型 `number` から object への局所 adapter であり、rc.2 の実 consumer は検証済みだが `typeof number` / `Number.isInteger` を前提とする第三者・将来 SDK には非互換で、一般保証はしない。Host への write・偽 `locale/change`・数値 revision の増加は行わず、source の `SHORTCUT(#80)` にも明記している。
- `scripts/pack-all.mjs` は `translation-status.json` が 64/2906・翻訳 2906・fallback 0・`complete` でない限り別の locale tarball を作らない。不完全な状態では `REFUSED` を表示して tarball を作らず、英語フォールバックの pack を黙って配布しない。`--require-locale` を付けたときだけその拒否を失敗にする。現在の status は `complete` なのでこのガードは通るが、リリース用の URL はなく、ローカルの tarball からのみ入れる。
- バッチレビューとマージは完了した（97 バッチのうち、seed 83 値を含む 3 バッチを除く 94 バッチ・2823 キーをマージ）。生成クライアントの登録は、実物の ClientModuleSystem と上流 locale bundle を使った隔離 Chrome で `modules.import` が成功し、64 名前空間 / 2906 キー / 65 disposers を確認済みである。GUI での確認は隔離した source 置換の証跡として #70 で別管理し、本番 profile への導入・実機確認とは区別する。この文書はリリース・本番導入・実機の成功を主張しない。
