# モバイルの戻る操作

Android の戻るキーと、iOS の画面左端から右へのスワイプで、表示中の画面から戻ります。

| 表示中の画面 | 戻る操作 |
| --- | --- |
| 終了確認 | 確認を閉じる |
| 画像の切り抜き、設定、ダイアログやメニュー | 表示中の画面を閉じる |
| セッション一覧のドロワー、右パネル | 開いているパネルを閉じる |
| プラグインや自動タスクの詳細 | 親の画面へ戻る |
| セッション、プラグイン一覧、自動タスク一覧 | ホームへ戻る |
| ホーム | 「終了しますか？」を表示する |

セッションからホームへ戻るときは、同じワークスペースの空のセッションを開きます。
そのワークスペースに再利用できる空のセッションがあれば、入力済みの下書きも引き継ぎます。
一覧画面の背後にホームがある場合は、ワークスペースと下書きを保ったまま一覧だけを閉じます。

終了確認の「キャンセル」はホームに留まります。「はい」はブラウザーの画面終了を試みます。
ブラウザーが終了を許可しない場合は、タブまたは端末のアプリ切り替え画面から閉じる案内を表示します。
Web/PWA から OS のタスクを強制終了することはできません。DSH サーバーの停止や、セッションの削除・中断は行いません。

iOS の戻るスワイプは左端 36px 以内から始め、右へ 64px 以上動かして指を離すと実行します。
縦方向に 24px を超えて動かした場合、複数の指で触れた場合、操作がキャンセルされた場合は戻りません。
入力欄、ターミナル、タブ列、右にスクロール済みの横スクロール領域では、その領域の操作を優先します。
Android のアプリ内左端スワイプは、従来の画面ごとの動作を維持します。PC の操作は変わりません。

Android のブラウザーが操作前に追加された履歴を飛ばす場合があるため、履歴の保護はページ内での最初の操作後に有効になります。
起動直後に一度も画面へ触れず OS の戻る操作をした場合は、ブラウザーの標準動作になる場合があります。

## 検証

`node --test packages/dsh-mobile-maxxing/tests/mobile-back.test.mjs` で、履歴からの戻る操作、画面階層、終了確認、スワイプの誤操作防止、再読み込み時の履歴重複防止を検証します。
実機の Android 戻るキー、iOS Safari の標準ジェスチャーとの競合、ホーム画面追加した PWA の終了可否は、端末ごとの確認が必要です。
