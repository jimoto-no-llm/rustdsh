# 探索用サブエージェントの制御

既存のDSHの `spawn` プロバイダーを利用する、任意導入のコード実装です。
`rdsh_explore` は履歴を引き継がない短い探索依頼に向いています。
自己完結した依頼と必要なファイルの場所を渡してください。
元の `subagent` や `subagent_fork` は別の用途として利用できます。

標準設定は同時3件、待機8件、待機期限120秒、出力上限4096トークン、深さ1、依頼64 KiBです。
同時3件は `rdsh subagents plan` の既定ウェーブ幅（`max_parallel` 3）に合わせています。
待機期限は実行1件分より長くないと待機枠が機能しないため、上限も600秒へと広げました。
有効な設定は `createOptimizer` が返す `limits` で参照できます。
親と依頼が指定したトークンおよび深さの上限が小さい場合は、そちらを優先します。
同じ親からの実行中の重複依頼は拒否します。完了・破棄後には同じ依頼を再実行できます。
結果のキャッシュや自動再試行はありません。

DSHがエージェントの作成、モデル選択、権限、出力スキーマ、ツール制限、破棄を担当します。
モデルは親または依頼の選択を維持します。安価なモデルへの自動切り替えは行いません。
待機中に親のモデル・作業場所・委譲権限の設定が変更された場合は実行を拒否します。
実行枠はネイティブの破棄が完了するまで保持し、破棄に失敗した場合でも新しい実行で埋めることはしません。
バックグラウンド継続、会話履歴のコピー、プロンプトの切り詰めには対応していません。

対応APIは `@deepseek-ai/dsh-subagent` / `dsh-tool-subagent` **0.2.0-rc.2** および **0.2.1-alpha.2** です。
両方の公開パッケージで、ネイティブヘルパー、ツール、UIスロットとの契約テストを通過しています。
Desktop SDKのCIでは、同梱する0.2.1-alpha.2との契約を3 OSで検証します。
同じバージョンの標準 `spawn` プロバイダーを有効にしてください。
対応していないプロバイダーへは実行を転送しません。

```sh
PROFILE=desktop SUBAGENTS=1 ./plugins/install.sh
# Web profile:
PROFILE=web SUBAGENTS=1 ./plugins/install.sh
# deterministic tests, no model or authentication calls:
node --test plugins/rdsh-subagent-optimizer/test/*.test.mjs
```

Desktopではアプリのプラグイン画面からこのディレクトリを追加することもできます。
プラグイン設定で上限を変更できます。同梱の `cordis.patch.yml` とコード既定値は同じ値であり、テストによって両者の一致を検証します。実際の費用や応答時間の改善率は測定していません。
