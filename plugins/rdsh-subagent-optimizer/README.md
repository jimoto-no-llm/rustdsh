# 探索用サブエージェントの制御

既存DSHの `spawn` プロバイダーを使う、任意導入のコード実装です。
`rdsh_explore` は履歴を引き継がない短い探索依頼に向いています。
自己完結した依頼と必要なファイルの場所を渡してください。
元の `subagent` / `subagent_fork` は別用途として利用できます。

標準設定は同時2件、待機8件、待機期限10秒、出力上限4096トークン、深さ1、依頼64 KiBです。
親と依頼が指定したトークン・深さ上限が小さければ、それを優先します。
同じ親からの実行中の重複依頼は拒否します。完了・破棄後には同じ依頼を再実行できます。
結果キャッシュや自動再試行はありません。

DSHがエージェントの作成、モデル選択、権限、出力スキーマ、ツール制限、破棄を担当します。
モデルは親または依頼の選択を維持します。安いモデルへの自動切り替えはしません。
待機中に親のモデル・作業場所・委譲権限設定が変わった場合は実行を拒否します。
実行枠はネイティブの破棄完了まで保持し、破棄失敗時にも新しい実行で埋めません。
バックグラウンド継続・会話履歴コピー・プロンプト切り詰めには対応しません。

対応APIは `@deepseek-ai/dsh-subagent` / `dsh-tool-subagent` **0.2.0-rc.2**です。
同じ版の標準 `spawn` プロバイダーを有効にしてください。
対応していないプロバイダーへは実行を転送しません。

```sh
PROFILE=desktop SUBAGENTS=1 ./plugins/install.sh
# Web profile:
PROFILE=web SUBAGENTS=1 ./plugins/install.sh
# deterministic tests, no model or authentication calls:
node --test plugins/rdsh-subagent-optimizer/test/*.test.mjs
```

Desktopではアプリのプラグイン画面からこのディレクトリを追加することもできます。
プラグイン設定で上限を変更できます。実際の費用・応答時間の改善率は測定していません。
