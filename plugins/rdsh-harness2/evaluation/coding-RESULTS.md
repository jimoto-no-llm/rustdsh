# コード修正・テスト比較: 2026-10-19

コードを編集し、公開テストを実行する課題で実モデル比較を行いました。未使用3課題の事前定義テストでは、通常版は2/3課題・非公開23/24件、固定合成版は3/3課題・非公開24/24件が成功しました。ただし、事後点検で合成版だけが失敗する別の境界ケースも見つかりました。品質が一律に改善するとは判断できません。

## 条件

- `cursor-sdk / composer-2.5`、rdsh 0.9.1、DSH 0.2.0-rc.2、Node 26.12.0、macOSで実行しました。本家harness2は `1cfe254e8d25b15f37048c3730134686abe60335` に固定しています。
- 本家 `run_parallel(k=1)` と `trivial_selection` を使用しました。TTL/LRUキャッシュ1課題で改善し、生成した`agg1`を固定して未使用3課題へ適用しました。
- 通常版は候補Markdownが空のnative rdshです。両版に同じ初期ソース・プロンプト・公開テストと、共通の読取・限定編集・固定テスト実行ツールを与えました。日常の全shellツールを使う通常作業とは異なります。
- 各課題は2モジュール、公開テスト2件、非公開テスト8件です。公開テストは初期状態で1 PASS / 1 FAIL。課題の成立は別の一時的な参照修正で確認済みです。[課題設計](coding-task-design.md)を参照してください。
- 非公開テストと採点結果は改善用の証拠へ含めません。各課題・各版を1回ずつ、通常版→合成版の順に実行しました。上限は24ステップ・600秒、テスト実行は15秒です。

## 未使用課題の結果

通常版の依存順序コードは、先頭ノードの自己循環を検出すると、後続ノードの欠落依存を検査する前にエラーを返しました。課題はグラフ全体の欠落検証を循環検証より先に行う契約です。事前定義の非公開テストがこの差を検出しました。

両版ともソース2ファイルだけを変更し、元の公開テストは不変でした。通常版の編集ツールは計7回・公開テスト実行4回、合成版は編集6回・公開テスト実行3回です。時間はnativeセッションのwall timeで、事後のホスト採点時間を含めません。平均で合成版が約17%遅く、単一回のため速度差も一般化しません。

## 事後に見つかった反例

全生成ソースの独立点検で、合成版のページ取得にカーソル衝突を発見しました。初期カーソル`null`を文字列`'\0__null__'`へ変換して既訪問管理しているため、次のページが同じ値の合法な文字列カーソルを返すと、循環と誤認します。

[追加の反例テスト](posthoc-cursor-collision.mjs)を両版の保存済みソースへ同条件で実行し、通常版1/1 PASS、合成版0/1 PASSを確認しました。これはソースを見てから追加した探索的な検査で、上表の事前定義成績へ加算していません。モデルを再実行したり、ハーネスを選び直したり、生成ソースを修正したりしていません。

## 改善処理の費用と失敗

改善用キャッシュ課題は通常版・最終合成版とも非公開8/8でした。改善処理は7セッション、通常実行1回に対する追加分は6セッション・281.9秒でした。未使用課題の6セッションを合わせて13セッションです。トークン使用量・金額はSDKが返さなかったため`null`です。

`dom1`の候補実行が`NATIVE_TURN_FAILED`となり、ソースを変更できませんでした。3件の改善提案はすべて検証を通過し、合成案`agg1`はfallbackではなく、ソース修正と公開テストを完了しました。この有効な合成案で比較を継続しましたが、改善処理全体の`adaptationComplete`と`overallComplete`は`false`のままです。未使用課題の比較完了とは区別しています。

- 実装にソースの限定編集、固定Nodeテスト、macOSのOS sandbox、コード課題アダプターとホスト採点を追加しました。実際のCordisツール経由で「失敗→編集→成功」と元テスト不変性を確認しています。

- 全10成果物のソース全文を独立点検し、出力偽装、強制終了、assert/test改変、global/prototype操作、追加テスト、外部I/Oによる採点操作は見つかりませんでした。ホスト採点は直接の`process`操作・組込みimport等も事前に拒否します。ただし、同じJavaScript環境で実装とテストを実行するため、任意の悪意あるコードに対する完全な採点隔離ではありません。
