# コード修正比較タスクの設計

`coding-tasks.json` は Node.js 標準ライブラリだけで動く、コード修正用の小規模課題集です。実モデルの成績は実験結果ファイルに分けます。この文書の数値は課題自体の事前検証です。

| 課題 | 用途 | 修正対象 | hiddenで確認する契約 |
| --- | --- | --- | --- |
| `ttl-lru-cache` | train | TTL/LRUキャッシュ、期限判定の2モジュール | falsey値、境界時刻、TTL=0、参照順序、更新、期限切れ除去、更新時の期限、入力検証 |
| `bounded-map-settled` | holdout | 並列処理制御、結果ラッパーの2モジュール | 完了順と入力順、グローバルindex、例外の局所化、並列数、空き枠の即時補充、limit検証、引数検証、thenable |
| `paginated-records` | holdout | ページ取得、重複統合の2モジュール | 最新レコードへの置換、型付きid、空文字cursor、cursor循環、ページ上限、設定検証、ページ検証、非破壊性と例外伝播 |
| `dependency-schedule` | holdout | 安定トポロジカル順序、入力検証の2モジュール | readyノード間の優先順、途中解放の優先順、重複辺、重複id、欠落依存、循環、入力検証、非破壊性 |

各課題は2個の公開テストと8個の独立hiddenテストを持ちます。公開テストは通常ケースが1個PASS、不具合再現ケースが1個FAILする状態から始まります。プロンプトには修正に必要な契約と境界条件を記載し、実装方法や正解コードは記載しません。課題側から `harness2_test` の実行を要求します。

train課題だけを設定改善に使い、holdout課題・hidden内容・採点結果は改善時に渡しません。通常版と改善版には同じソース、公開テスト、プロンプト、実行権限を渡します。モデルが変更してよいファイルは各課題の `editableFiles` に明記したsrcの2ファイルです。

hiddenテストはモデルの作業ディレクトリの外に置き、`RDSH_FIXTURE_ROOT` に検査対象の作業ディレクトリを指定します。hidden側は `pathToFileURL` で修正済みソースを読み込みます。相対パスでhidden配置先に依存せず、修正を行うモデルにhiddenファイルを配置する必要もありません。公開テストは通常どおり `../src/` を参照します。各hiddenファイルはflatな `test()` 8個で、subtestは使いません。

並列課題は実時間sleepを使わず、Promiseのゲートで完了順・同時実行数・空き枠の補充を検査します。ゲートの観測前には12回microtaskを処理します。外部通信、追加パッケージ、モデル、資格情報、実ファイルの書き換えは不要です。

事前検証では使い捨てディレクトリに初期ファイルを展開し、別ディレクトリのhiddenを `node --test --test-reporter=tap` で実行しました。その後、課題集やモデル向け作業ディレクトリに含めない一時的な参照修正を適用し、全公開・hiddenテストが成立することを確認しました。

| 課題 | 初期public PASS/FAIL | 初期hidden PASS/FAIL | 参照修正public PASS/FAIL | 参照修正hidden PASS/FAIL |
| --- | --- | --- | --- | --- |
| ttl-lru-cache | 1 / 1 | 0 / 8 | 2 / 0 | 8 / 0 |
| bounded-map-settled | 1 / 1 | 2 / 6 | 2 / 0 | 8 / 0 |
| paginated-records | 1 / 1 | 1 / 7 | 2 / 0 | 8 / 0 |
| dependency-schedule | 1 / 1 | 2 / 6 | 2 / 0 | 8 / 0 |

合計は初期public 4 PASS / 4 FAIL、初期hidden 5 PASS / 27 FAIL、参照修正public 8 PASS / 0 FAIL、参照修正hidden 32 PASS / 0 FAILです。これらは通常版・改善版のモデル成績ではありません。

この課題集は小規模で、プログラム全体の設計・大規模リポジトリ探索・非同期I/O障害までは評価しません。hiddenテストは契約の代表ケースであり、完全な正しさの証明ではありません。比較ではhidden通過数に加えて、公開テストを実行したか、src以外の変更がないか、所要時間、実行失敗を記録すると差を判断できます。
