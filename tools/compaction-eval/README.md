# compaction-eval

圧縮の要約指示を評価し、改善するための開発用の道具です（RQ-11）。
rdsh の実行時の処理には含まれません。実行時へ渡すのは、採用した指示の文だけです。

圧縮そのものは作り直していません。本物の `rdsh` と DSH の headless を、
1 回ごとに作る専用のホームで起動し、実行時と同じ圧縮の経路を使います。

## 使い方

```sh
cp eval.example.json eval.json   # 接続先、モデル、しきい値を書く
node cli.mjs check --config eval.json    # タスクと設定の検査。モデルは呼びません
node cli.mjs run --config eval.json      # 基準、候補、最終確認、書き出し
node cli.mjs status --config eval.json   # 進み具合
```

`dshRuntime` には、`node_modules/@deepseek-ai/dsh` が入っているフォルダを指定します。
API キーは設定ファイルに書きません。`provider.apiKeyEnv` に環境変数の名前を書きます。
接続先は OpenAI 互換の Chat Completions です。

## 手順

1. 条件を固定して、圧縮なし（`none`）と、今の指示（`current`）で基準を取ります。
2. 改善用のタスクで、圧縮なしでは成功し、圧縮の後で失敗したものを比べます。
3. 要約が何を落としたかをモデルに聞き、指示の候補を作ります。
4. 候補を選択用のタスクで評価し、決めてある条件で採否を決めます。
5. 最終確認用のタスクで、今の指示と比べ直します。通った時だけ指示を書き出します。

書き出すファイルは、`stateDir` の中の次の 3 つです。

| ファイル | 中身 |
| --- | --- |
| `result.json` | 件数、トークン数、採否の理由。会話の本文は入りません |
| `instructions.txt` | 採用した指示の文 |
| `rdsh-compaction.candidate.json` | `rdsh-compaction.json` の `instructions` に写すための形 |

採用しなかった時と、予算が尽きた時は、指示を書き出しません。今の指示がそのまま残ります。

## 決めてあること

- 合否は、最後の答えの JSON を、タスクに書いた値と比べて決めます。モデルの自己申告は使いません。
- タスクは、改善用（`improve`）、選択用（`select`）、最終確認用（`final`）に分けます。
  候補を作るプロンプトに入るのは、改善用のタスクだけです。
- 圧縮なしでも失敗したタスクは、失敗の比較から外します。結果には残します。
- 採用の条件は、評価の前に決めてあります。必須のタスクに新しい失敗がなく、
  成功数を保ってトークン数を下げるか、上限の中で成功数を増やした時だけ採用します。
- 候補の実行で圧縮が 1 回も起きなかった時は、採用しません。
- 終わった実行は、タスク、指示、モデル、しきい値が同じなら再利用します。
  始めて終わっていない実行は、`--retry-interrupted` を付けた時だけ送り直します。
- モデルのツールは、ふつうは止めて実行します。
- `tools: true` のタスクだけ、ファイルのツールを使えるようにします。サンドボックスは読み取り専用で、
  作業フォルダにはそのタスクのファイルだけを置きます。シェル、Web、サブエージェントのツールは、どの実行でも止めます。
- ツールを使うタスクの合否には、操作の記録も使います。ツールを呼んだ回数と、作業フォルダにファイルができていないことです。

既定の予算は、2 ラウンド、各 2 候補、同時実行 1 件、実行は 60 回までです。
探索する量の上限で、品質の保証値ではありません。

## まだ無いもの

- タスクは 9 つです。制約、パス、決定の更新、構造化した出力が 6 つで、ツールを使うものが 3 つです
  （ツール結果の照合、失敗の後の継続、拒否された操作の保持）。ツールを使うタスクは、種類ごとに 1 つずつしかありません。
  ツールを使う 3 つは、圧縮なしと今の指示の 2 つの条件で、実モデルで 1 回ずつ走らせて、どれも合格でした（2026-11-11）。
- 実モデルでの通しは 1 回だけです（2026-11-11、OpenAI 互換の 1 モデル、実行 12 回、呼び出し 109 回）。
  改善用の 1 タスクが圧縮の後で失敗し、候補を 2 つ作りましたが、選択用のタスクで改善が無く、採用はありませんでした。
  少ない試行の結果を、一般的な品質の改善とは言いません。
- native-web の経路は対象にしていません。対象は DSH の headless です。

## テスト

```sh
npm test
RDSH_BIN=/path/to/rdsh RDSH_DSH_RUNTIME=/path/to/runtime npm test
```
