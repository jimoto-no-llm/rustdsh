# rdsh: 一行から、つながる

## 判断

前版は参考の白い空間・青い金属・点群・中央のコピー・立体端末を
まとめて採用し、rdshより参考動画の印象が勝っていた。
今回はrdshのネイティブコマンドとプロジェクト状態の確認を主題にする。
文字を飾る映像ではなく、入力が検索結果、タスク、回答へ進む映像。

## デザイン

色: 冷たい灰 #e8e9e6、紫墨 #382c46、オレンジ #e8743b、
紙白 #f8f9f6、淡い紫 #ded7e7、状態の緑 #337a67。
Noto Sans JPの600–700を主役に、Instrument Sansをロゴ、
DejaVu Sans Monoを実際のコマンド表示に使う。

左に日本語コピー、右に具体的な作業結果。中央寄せの標語を繰り返さない。
細い線はコマンドの入力と結果の関係を示す。オレンジの四角は
カーソルから検索箇所、作業状態、回答の保存へ役割を変える。
独自のビジュアル上の記憶点は、この四角とL字の通り道。

三案を比較した: 抽象3D、新聞風タイポグラフィ、コマンドから結果へ
つながる入力の軌跡。前二者は他製品でも成立するため、第三案を採用。
背景テクスチャ・常設の章番号・回転する機器は使わず、操作に対応する
形の変化と、入力と出力の関係だけに動きを与える。

## 編集

44秒、1920×1080、60fps。マクロのコマンドから始まり、検索、
ネイティブ処理、タスク、回答、手元の表示、導入へ進む。
前版の構成や演出を変更して新規実装。既存の監査済みデモ画面だけ再利用。

| 秒 | 場面 | 動きの理由 |
| --- | --- | --- |
| 0–4.5 | プロンプトからrdshの名前 | 入力が製品の名前を作る |
| 4.5–12 | searchとtokens | 入力と実際の出力が左右で対応する |
| 12–17 | Rustで処理するコマンド | コマンドが処理レーンへ収まる |
| 17–25 | プロジェクトのタスク | カーソルが作業状態へ変わる |
| 25–33 | 質問と回答保存 | 送信によって問いが回答済みに変わる |
| 33–38 | スマホ幅の状態表示 | 同じ情報が別の画面へ続く |
| 38–44 | rdshと導入案内 | 軌跡がプロンプトへ戻る |

## 音

ユーザー指定: 落ち着いたリズム＋操作音。前の自動アルペジオを廃止。
利用条件を確認した穏やかな既成曲を短く編集し、入力、Enter、
回答保存に小さな打音を置く。常に同じループを鳴らさず、
操作音が聞こえるようBGMの音量を落とす。楽曲は終わりにクレジット。

## 個人情報

空のHOMEと新しいブラウザーで撮った架空のデモだけを使用。
既存の画面、アカウント、ファイル一覧、キー、接続URLは映さない。
