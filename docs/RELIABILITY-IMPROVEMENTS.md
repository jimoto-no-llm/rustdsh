# 信頼性改善リスト — DSH 運用で発生した不具合から

Node 実装の DSH (0.2.2-rc.1) を実運用した際に発生した不具合を分析し、rustdsh 側で予防・改善するための項目をまとめる。

観測環境: Fedora / systemd user service / 2026-11-06 時点。発生データは journalctl と API 実検証に基づく。

## 1. ワークスペースディレクトリ消失時のターン即失敗

- **発生**: 登録ワークスペースの実ディレクトリが消えた状態でターンを開始すると、`working-directory: directory does not exist` で即座に失敗する。空ディレクトリの自動再作成は失敗後の次回試行時まで行われず、失敗したターンはユーザーが再送する必要があった
- **改善案**: ターン開始時・セッション作成時に cwd を `mkdir -p` で自動修復し、警告を 1 回だけ出す。作成できない場合のみターンを失敗させる
- **効果**: ワークスペース移動・整理の作業中でもセッションが壊れなくなる

## 2. 無効な LLM API キーの起動時検証欠如

- **発生**: `DEEPSEEK_API_KEY` が別サービス用のキー形式 (`sk-sp-` prefix・114 文字) に差し替わっており全リクエストが 401。DSH は `model listing failed ... using the bundled catalog` とフォールバックして起動を続け、ユーザーにはセッション単位の「This session had an error」としてしか見えない。11/4〜11/6 の 3 日間継続
- **改善案**: 起動時 (またはプロバイダ設定変更時) に `/models` 相当の軽量検証を行い、無効なら UI に警告バッジを表示。セッション作成時にも通知する。キー形式の基本的なバリデーション (公式キーは `sk-` + 32 hex など) も選択肢
- **効果**: キー切替・更新ミスが即日発見できる。原因不明のセッションエラーが減る

## 3. 本体更新とプラグイン更新の分離によるバージョン不整合スパム

- **発生**: dsh 本体を 0.2.2-rc.1 に更新した際、dsh-mcp-client が 0.2.1-rc.4 のまま残り、MCP 14 row が起動のたびに無効化ログを出力 (10/30〜11/5 の 7 日間で 1,638 行)
- **改善案**: 本体更新時に互換プラグインを同時更新する (アトミック更新)。不整合警告は 1 回だけ記録し、以降は抑制する
- **効果**: 更新後の MCP 全滅とログスパムを防ぐ

## 4. MCP サーバー起動失敗のクラッシュループ

- **発生**: 認証トークン未設定の slack-mcp-server / gmail-mcp がサービス起動のたびに `npx` 起動→即死を繰り返した (1 回の起動で slack 22 回、gmail 44 回)。ログ汚染と起動遅延の原因になった
- **改善案**: MCP サーバーに指数バックオフ＋サーキットブレーカーを入れる。起動前設定検証を行い、必須 env が不足していれば起動せず UI に「設定不足」と一覧表示する
- **効果**: 設定漏れが視える化され、起動時の無駄なプロセス生成がなくなる

## 5. `link:` 依存のリンク先消失検出

- **発生**: profile の package.json にある `link:` 依存 6 本の指すディレクトリ群が一括削除され、動かないプラグインが静かに残存した。次の `pnpm install` が失敗するまで気付けない
- **改善案**: 起動時に `link:` 依存のリンク先存在チェックを行い、切れていれば UI に一覧表示する
- **効果**: プラグイン移動・削除後のリンク切れを即発見できる

## 6. ツール引数検証失敗の修復リトライ

- **発生**: 特定モデルで長い引数・並列のツール呼び出しが断続的に `invalid arguments: missing required property` で失敗。サーバーログに記録されず原因追跡も困難だった (1 セッションで 6 回)
- **改善案**: 引数スキーマ検証の失敗時に、検証エラー内容を添えて 1 回だけ修復リトライする。検証エラーはデバッグログに記録する
- **効果**: モデル側の JSON 生成揺らぎに強くなり、デバッグもできる

## 優先順位案

1. #2 (キー検証) — 3 日間継続した全滅系不具合の直接防止
2. #1 (ワークスペース自動修復) — ターン失敗の即効性のある防止
3. #4 (MCP バックオフ) — 起動時の安定性
4. #5 (リンク切れ検出) — 設定の見える化
5. #3 (アトミック更新) — 更新手順の改善
6. #6 (修復リトライ) — モデル互換性の向上
