# ローカル環境を診断する

```sh
rdsh doctor
rdsh doctor --json
```

通常表示は元のDSH、プロファイル、Desktop、認証の概要、ラッパーを確認します。
DSHの `--version` は最大2秒、標準出力は最大4 KiBの取得に制限します。
応答しない場合はバージョン行を省略し、起動した子プロセスを終了・回収します。
DSHの子孫プロセスや、他のDSHセッションへの終了操作は行いません。

`--json` はCLI・エディター・MCPクライアント側で扱うためのメタデータ診断です。
認証ファイルを読まず、DSH・Nodeを起動せず、設定やクライアント登録を書き換えません。
元の実行ファイル、Node、プロファイル、Desktopの既存設定とPATHを調べます。
JSONにはローカルパスが含まれるため、共有時には必要に応じてパスを伏せてください。

## JSONの契約

標準出力にJSONオブジェクトを1つ出します。キーの順序には依存しないでください。
`schema` が対応する値かを確認し、未知のキーは無視します。

| キー | 内容 |
| --- | --- |
| `schema` | スキーマ番号。現在は `1` |
| `ok` | 元のDSHがファイルとして利用可能で、`.js` の場合は対応するNodeも見つかったか |
| `rdsh_version` | 実行中のrdshのビルドバージョン |
| `dsh_home` | このプロセスで解決したDSHの保存先 |
| `original.found` / `path` | 元のDSHの存在・実行権限と選択したパス。未検出時のパスは `null` |
| `original.probed` | 常に `false`。起動・バージョン取得は実施しない |
| `node.required` / `found` / `path` | `.js` のためにNodeが必要か、選択されたNodeの有無とパス |
| `profiles.readable` / `count` | プロファイルディレクトリを開けたか、配下のディレクトリ数。開けない場合は `null` |
| `desktop.app` / `profile_initialized` / `enabled_bundled_plugins` | Desktopアプリのパスと予約プロファイルの状態 |
| `path_shadowed` | PATHで最初に解決した `dsh` がこのrdshか、または `dsh` として起動されたか |
| `warnings` | 任意のプロファイルや、壊れる可能性があるラッパーへの補足。文字列の文言は解析しない |

Nodeの選択は実際の委譲と共有しています。元のDSHを含む対応OS・CPUの
`node-v*` ツリーを優先し、PATH、新しい対応ツリーの順で探します。
`found` はファイルの検出であり、Nodeのバージョン・ネイティブ依存関係・モデル接続の
成功を保証するものではありません。シェルスクリプト内の依存関係も解析しません。

終了コードは、必要なローカル実行ファイルが揃っていれば `0`、不足すれば `1` です。
不足していてもJSONを出力し、標準エラーに短い説明を出します。
任意のDesktopやプロファイルが未導入でも、それだけでは失敗にしません。
CLI引数・既存のrdsh設定が不正な場合は、診断前に失敗しJSONを出せないことがあります。

## ラッパーとPATH

PATHの後方にrdshへの `dsh` エイリアスがあっても、前方の実行可能なDSHを優先します。
Windowsでは `PATHEXT` の順序も使います。
`~/.local/bin` のラッパー確認は、コメント行を除き、同じ行で `node` と
`$(command -v dsh)` / `$(which dsh)` または対応するバッククォートを使う場合を示します。
明示的な `node /path/to/dsh/index.js` はこの警告の対象にしません。
変数経由や複数行のスクリプトまで解析するシェルパーサーではありません。

## MCPから使う場合

この診断はRustランチャーをDSHと併用する環境向けです。
独立したNodeダッシュボードはDSHを必要としないため、`ok: false` でも接続できる場合が
あります。[MCP導入ガイド](MCP-CLIENTS.md)に従って `dashboard_get_state` で接続を確認します。
認証やモデルを確認する操作は診断の後、各クライアントの権限と通常の設定手順で行います。
