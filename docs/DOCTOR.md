# ローカル環境を診断する

```sh
rdsh doctor
rdsh doctor --json
```

通常表示では、元のDSH、プロファイル、Desktop、認証の概要、およびラッパーを確認します。
DSHの `--version` の実行は最大2秒、標準出力の取得は最大4 KiBに制限します。
応答しない場合はバージョン行を省略し、起動した子プロセスを終了して回収します。
DSHの子孫プロセスや、他のDSHセッションに対する終了操作は行いません。

`--json` はCLI・エディター・MCPクライアント側で処理するためのメタデータ診断です。
認証ファイルを読み込まず、DSHやNodeを起動せず、設定やクライアント登録も書き換えません。
元の実行ファイル、Node、プロファイル、Desktopの既存設定とPATHを調べます。
JSONにはローカルパスが含まれるため、共有時には必要に応じてパスを伏せてください。

## JSONの契約

標準出力にJSONオブジェクトを1つ出力します。キーの順序には依存しないでください。
`schema` が対応する値であるかを確認し、未知のキーは無視してください。

| キー | 内容 |
| --- | --- |
| `schema` | スキーマ番号。現在は `1` |
| `ok` | 元のDSHがファイルとして利用可能で、`.js` の場合は対応するNodeも見つかったか |
| `rdsh_version` | 実行中のrdshのビルドバージョン |
| `dsh_home` | このプロセスで解決したDSHの保存先 |
| `original.found` / `path` | 元のDSHの存在・実行権限と選択したパス。未検出時のパスは `null` |
| `original.probed` | 常に `false`。起動・バージョン取得は行いません |
| `node.required` / `found` / `path` | `.js` のためにNodeが必要か、選択されたNodeの有無とパス |
| `profiles.readable` / `count` | プロファイルディレクトリを開けたかどうかと、配下のディレクトリ数。開けない場合は `null` |
| `desktop.app` / `profile_initialized` / `enabled_bundled_plugins` | Desktopアプリのパスと予約プロファイルの状態 |
| `path_shadowed` | PATHで最初に解決した `dsh` がこのrdshか、または `dsh` として起動されたか |
| `warnings` | 任意のプロファイルや、壊れる可能性があるラッパーへの補足。文字列の文言は解析しません |

Nodeの選択ロジックは実際の委譲処理と共通です。元のDSHを含む対応OS・CPUの
`node-v*` ツリーを優先し、PATH、より新しい対応ツリーの順に探索します。
`found` はファイルの存在検出を示すものであり、Nodeのバージョン・ネイティブ依存関係・モデル接続の
成功を保証するものではありません。シェルスクリプト内の依存関係も解析しません。

終了コードは、必要なローカル実行ファイルが揃っていれば `0`、不足していれば `1` です。
不足している場合でもJSONを出力し、標準エラー出力に簡単な説明を出します。
任意のDesktopやプロファイルが未導入であっても、それだけでは失敗とはみなしません。
CLI引数や既存のrdsh設定が不正な場合は、診断前に失敗してJSONを出力できないことがあります。

## ラッパーとPATH

PATHの後方にrdshへの `dsh` エイリアスがあっても、前方にある実行可能なDSHを優先します。
Windowsでは `PATHEXT` の順序も考慮します。
`~/.local/bin` のラッパー確認では、コメント行を除き、同一行で `node` と
`$(command -v dsh)` / `$(which dsh)` または対応するバッククォートを使用している場合を検出します。
明示的な `node /path/to/dsh/index.js` はこの警告の対象外です。
変数経由の指定や複数行にわたるスクリプトまで解析するシェルパーサーではありません。

## MCPから使う場合

この診断はRustランチャーをDSHと併用する環境向けです。
独立したNodeダッシュボードはDSHを必要としないため、`ok: false` であっても接続できる場合が
あります。[MCP導入ガイド](MCP-CLIENTS.md)に従って `dashboard_get_state` で接続を確認してください。
認証やモデルを確認する操作は診断の後、各クライアントの権限と通常の設定手順に従って行います。
