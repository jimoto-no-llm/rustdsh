## 0.11.0 — サイドバーの Feedback 行を消し、リリース経路を固める

- リリースビルドの `uses:` を 40桁コミット SHA に固定しました。可変 ref の上流書き換えで
  公開バイナリへ任意コードが混入する経路を塞ぎます（#890）。
- CD は安定版を `--latest=false` で公開し、digest 台帳が main に入った時点で
  `mark-release-latest` が Latest を切り替えるようにしました。台帳 pin 前に documented な
  導入コマンドが旧版を入れる食い違いが起きません（#892）。
- `rdsh search` と `rdsh search-web` の人間向け出力から制御文字を除きました。検索対象の
  ファイル名・一致行・検索結果の URL に ESC や OSC 52 が入っていても、端末の行消去や
  クリップボード書き換えが起きません（#889、#896）。機械可読出力は従来どおりです。
- rdsh が `$DSH_HOME` を最初に作るとき、ディレクトリを 0700 で作成するようにしました
  （umask に依存しません）。既存ディレクトリのモードは変更しません（#891）。
- `.credentials.yaml` が他ユーザーから読めるモードのとき、読み込み時に警告するようにしました
  （dsh は 0600 以外を読まないため、黙って空になるのを避けます）（#893）。
- サイドバーのアカウントメニューに残る **Feedback** 行を隠す `rdsh-no-feedback-client` を
  追加しました。DSH は Settings / Feedback / Sign in を固定で組み立てており、既存の
  `rdsh-no-feedback` だけでは行が残って機能しないフォームを開いていました。サインアウト時の
  メニューに限って非表示にし、`features.feedback` が off のとき本体と一緒に導入されます。
- `rdsh provider add` が、モデルの画像入力対応を自動で判定して `input: [text, image]` を
  書くようにしました。Ollama 系は `POST /api/show` の `capabilities` を、それ以外は
  `GET /models` の `architecture.input_modalities`／`input_modalities`／`capabilities` を
  読みます。手動指定は `--input text,image`（`text` は必須、未知の値は拒否）。宣言が無い
  モデルには `input:` を書かず、dsh の既定（テキストのみ）に任せます。

## 更新前に確認

- 対応プラットフォームは Linux x86_64（glibc / musl）、macOS arm64・x86_64、Windows x86_64 です。
- 必要なもの: 更新元の `dsh`（@deepseek-ai/dsh）が導入済みで PATH にあること。ソースから
  ビルドする場合のみ Rust 1.85 以上が必要です。
- 互換性: 設定・プロファイル・プラグインの移行は不要です。既存の `rdsh-no-feedback` を
  使っている場合、`plugins/install.sh` か `rdsh plugins install` を再実行すると
  `rdsh-no-feedback-client` も一緒に導入されます（`rdsh features on feedback` なら入りません）。
  新しいプラグインは Web UI の再読み込み後に効きます。
- 更新後は既存の rustdsh プロセスを再起動してください。
- 版の判定: minor（新しい同梱プラグイン `rdsh-no-feedback-client` の追加と、`rdsh provider add`
  が画像入力対応を自動判定するようになったため。既存の設定は書き換えません）。

Install/update:

```sh
curl -fsSL https://github.com/jimoto-no-llm/rustdsh/releases/latest/download/install.sh | bash -s -- --from-release
```

Windows では同じ Release の `install.ps1 -FromRelease` を使用してください。
