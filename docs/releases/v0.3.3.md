## 0.3.3 — 導入の安全性と認証まわりの修正版

- **インストーラの検証を強化**: `install.sh --from-release` が、アーカイブ横のチェックサムではなく**このリポジトリの `release-digests.tsv` に固定したダイジェスト**で検証するようになりました。配布元が差し替えられても、別のペイロードは導入されません（Unix のみ。Windows の `install.ps1` は sidecar 方式のままです）。
- **Windows の実行ファイル乗っ取り対策**: ダッシュボードが PowerShell トレイ、URL ハンドラ、インストール済み CMD ラッパーを絶対パスで起動するようになりました（作業ディレクトリに置かれた `pwsh.exe` や `rundll32.exe` を読み込みません）。既存の `rdsh-dashboard.cmd` はインストーラを再実行して更新してください。
- **委譲の判定を修正**: `PATH` 上の `dsh` / Node 候補を「実効権限で実行できるか」で判定するようになり、実行権限のない候補によって `Permission denied` が発生しなくなりました。
- **認証情報のロック互換**: 上流 DSH と同じ credential lock 方式に合わせ、rustdsh の使用後に認証情報の保存・更新がタイムアウトしなくなりました。
- `rdsh guard --policy-file` で Read/Write/Edit を構造化して判定できるようになりました（未指定時の挙動は従来どおりです）。
- Dashboard のロック後始末が「コミット済みの書き込み」を隠さないように修正しました（元のエラーコードを保持し、`lock_cleanup_unconfirmed` を添付します）。
- `rdsh_inspect` のパラメータを正しい JSON Schema で宣言し、厳格な検証でも通るようにしました。
- インストーラが Windows アイコンの ICO ヘッダおよびペイロード範囲を再構築前に検証するようになりました。
- `rdsh-docs` スキルを同梱し、DSH web プロファイルから rustdsh の挙動を確認できるようにしました（実機での受入確認は継続します）。
- Dashboard が worker 差分を固定コミット順に統合し、全チェックへの合格を必須としました。
- 依存関係の更新: `sha2` 0.11（16進エンコードを明示実装）、`embed-resource` 3.0.12、`koffi` 3.3.3、`@agentclientprotocol/sdk` 1.8.0。

## 更新前に確認

- 対応プラットフォームは Linux x86_64（glibc / musl）、macOS arm64・x86_64、Windows x86_64 です。導入手順は 0.3.2 から変更ありません。
- **install.sh の検証方法が変わります**: `--from-release` は毎回 `raw.githubusercontent.com` から台帳を取得し、取得できない場合は導入を拒否します（fail-closed）。閉域網で導入する場合は、アーカイブと sidecar を明示的に指定する従来の手順を使用してください。
- 会話とモデル応答は本家 DSH のままで、互換性は維持されます（DSH **0.2.0-rc.2** と **0.2.1-alpha.1** を認識）。
- 移行作業は不要です。既存の `rdsh` は同じコマンドで上書き更新できます。
- 設定は `$DSH_HOME/rdsh.json` のままです。今回の修正によるキーや既定値の変更はありません。
- 更新後は既存の rustdsh プロセスを再起動してください。

Install/update:

```sh
curl -fsSL https://github.com/jimoto-no-llm/rustdsh/releases/latest/download/install.sh | bash -s -- --from-release
```

Windows では同リリースの `install.ps1 -FromRelease` を使用してください。
