## 0.6.0 — guard の照合強化と doctor・ベンチの是正

- **guard の deny 照合を強化（セキュリティ改善）**: `rdsh guard` が deny パターンを照合する前にコマンド文字列をシェル構文として解析するようにしました。クォート分割（`r"m" -rf`）、同一行での変数組み立て（`A=rm; $A -rf`）、コマンド実体名（`/bin/rm -rf /`）、入れ子の引用コマンド（`sh -c "rm -rf /"`）、`..` の畳み込みとシンボリックリンク解決を含むパス脱獄、の5系統の難読化・すり抜けをブロックします。判定は引き続き構造的なパターン照合で、許可リストではありません。ブロック時は従来どおり終了コード2と同一の stderr を返し、通常のコマンドでの性能劣化はありません（#708）。
- **doctor の探索と診断を拡充**: `rdsh doctor` が本家 `dsh` を nvm・volta・fnm・pnpm・`npm -g` の各ディレクトリからも探索するようになりました。非対話シェルや systemd サービスでは初期化スクリプトが動かず、導入済みでも「original dsh」が空になる問題に対応します。PATH とローカルバックアップの解決順は維持し、nvm の `~/.nvm/versions/node/vX.Y.Z` 形式も Node 探索の対象に加えています。あわせて Node/npm/pnpm の環境ブロック（en/ja/zh、`doctor --json` では `environment`）と、pnpm のビルドスクリプト方針（インストール済み pnpm に対応した承認コマンド付き）を表示します。警告は終了ステータスを変えず、判定は従来どおり本家 `dsh` のみに依存します（#707）。
- **フック計測ベンチの追加と数値の是正**: PreToolUse フック（`rdsh guard`）と `rdsh tokens`・`rdsh search` を、同一データセット上の等価な Node.js 実装と比較するベンチ（`scripts/benchmark-node-vs-rust.py` と `scripts/benchmark-node-reference.mjs`）を追加しました。出力一致を検証してから計測し、生サンプル付きの JSON レポートを生成します。README・README.ja・`docs/BENCHMARKS.md` は各数値が測った対象を明記するよう修正し、**約0.90ms は `--version` のプロセス起動のみ**、**PreToolUse フックはプロセス起動を含めて実測約2.0ms/呼び出し**であることを示しました（#706）。
- **`rdsh serve` を「監査・パフォーマンスモニター」として明示**: ヘッダーに DeepSeek Harness 向けの Audit & Performance Monitor という役割を英・中・日で表示し、トークン入力前にビルドバージョンと役割の概要を描画します。接続後は doctor 診断・セッション・スキルのカードを並列で埋めるため、初回表示が空のチャット画面に見えなくなりました（#705）。
- **旧リポジトリURLの統一**: `dashboard/README.md`、`docs/evidence/*.md`、workflow-board の README に残っていた旧 `sahenjp/rustdsh` の issue / PR リンクを、正規の `jimoto-no-llm/rustdsh` へ向け直しました。旧 `issues/N` はリダイレクトせず 404 になるためで、歴史的な記述・issue番号・コミット参照はそのまま保持しています。統一前に開かれた PR のリンクも解決するよう、docs のリンクチェックの remap は残しています（#704）。

- **推奨プラグインを選んで導入（Essential / Recommended）**: `plugins/install.sh` が **Essential**（毎回導入し、先頭に表示）と **Recommended**（任意）を区別するようになりました。`--recommended=all|none|list|id,...`（または `RECOMMENDED` 環境変数）で非対話でも導入対象を指定でき、TTY では推奨プラグインの一覧を見せて確認します。非対話時の既定は従来のプロファイル別のままで、カタログと階層は `plugins/recommended.md`・README・`docs/DESKTOP-INTEGRATION.md` に記載しています（#713）。
- **Fedora/RHEL 系の前提チェックと次の一手**: `install.sh` がダウンロードやビルドの前に、必要なツール（`curl`・`tar`・`gzip`・coreutils）、Node.js 22+ と本家 `dsh` の状態、`PREFIX` の書き込み可否を確認し、ホスト自身の導入コマンド（rpm 系は `sudo dnf install -y ...`、ほかは Debian・Alpine・Arch・openSUSE の相当コマンド）を表示します。Fedora・RHEL・CentOS・Rocky・AlmaLinux・Oracle Linux では任意の `zstd`/`bubblewrap`、`PATH` のヒント、glibc か静的 musl かの選択理由も案内し、musl を前提にしません（#714）。
- **サブエージェント既定値の見直しと可変化**: サブエージェント探索プラグインの同時実行の既定が2件から**3件**になり、既定の `rdsh subagents plan` の1ウェーブが待ち行列なしで走ります。待機の既定は10秒から**120秒**、上限は60秒から**600秒**へ広げ、`cordis.patch.yml` も同じ値に固定しました。あわせて `rdsh subagents defaults [--json]` が計画に適用される上限と `source`（`settings`/`builtin`）を表示し、`rdsh.json` の `subagents` 節（`max_parallel`・`max_items_per_agent`・`max_weight_per_agent`・`budget_units`）で上書きできます。要求側の `limits` は常に優先し、設定が欠落・破損しているときは組み込み既定で計画を続けます（#715）。
- **Web UI の操作感（UI comfort）**: クライアントプラグイン `plugins/rdsh-ui-comfort` を追加しました。送信欄では素の Enter が改行になり、**1.5秒以内の2回目の Enter** で送信します。ゴール編集中は Enter（IME の変換確定 Enter を含む）で確定せず、Ctrl/Cmd+Enter かチェックボタンで確定、Escape で取り消します。両機能とも既定で有効で、`rdsh 入力` 設定からその場で切り替えられます。プロファイルへは `dsh plugin --profile web add <repo>/plugins/rdsh-ui-comfort` で追加します（#716）。
- **訳文でモデル可視の履歴を置換（#448 Step 2）**: `plugins/rdsh-translation` のアクション行に「日本語訳で置き換える」を追加しました。明示操作のときだけ `/ja-replace` が独立した翻訳を1回送り、対象回答の surface ノードを訳文に置き換えます。新しいターンも追指示の user メッセージも追加せず、元の回答は追記専用ログと人間向け transcript に残ります。**既知の制約**として、DSH が置換をモデル可視 surface だけに適用する設計のため、画面上の回答表示は差し替わりません（訳文はダイアログで確認できます）。画面表示も置き換えるには DSH 側に置換を表示へ反映する API が必要です（#718）。
- **Windows tray の ready 判定を進捗ベースに**: `dashboard/windows-tray.mjs` が起動からの絶対時計ではなく、観測した進捗の間の無音時間（`TRAY_READY_STALL_MS`）で ready を待ち、spawn 時と各 startup phase で待ち直すようにしました。コールド起動中で生存している helper を締切で殺さなくなり、診断に `last_event`/`quiet_ms` を追加しています（#717）。

## 更新前に確認

- 対応プラットフォームは Linux x86_64（glibc / musl）、macOS arm64・x86_64、Windows x86_64 です。導入手順は 0.5.2 から変更ありません。
- 会話とモデル応答は本家 DSH のままで、互換性は維持されます（DSH **0.2.0-rc.2**、**0.2.1-alpha.1**、**0.2.1-alpha.3** のランタイムを認識）。
- 移行作業は不要です。`rdsh.json` の既存キーや既定値は変わりません。`rdsh guard` の設定キーとブロック契約（終了コード2・stderr）も 0.5.2 と同一です。
- **`rdsh guard` はセキュリティ改善です**: deny パターンを難読化で迂回しようとするコマンドが新たにブロックされます。正規の運用コマンドが誤って対象になる場合は、deny パターン側の見直しで対応してください。
- **ベンチ数値の注意**: README / BENCHMARKS の数値は特定の Linux x86_64 ホスト・`n=15` の実測で、ホストや負荷により変わりえます。`--version` 以外の行は本家 `dsh` ではなく Node.js 参照実装との比較です。数値の再取得手順は `docs/BENCHMARKS.md` を参照してください。
- **サブエージェントの既定値が変わりました**: 既定の同時実行は3件、待機は120秒（上限600秒）です。以前の値に合わせたい場合は `rdsh.json` の `subagents` 節で指定してください。
- **訳文置換はモデル可視の履歴だけを置き換えます**: 画面上の回答表示は変わらないため、表示の差し替えには DSH 側 API が必要です。
- ソースからビルドする場合は Rust 1.85 以上が必要です（配布バイナリの利用に Rust は不要）。
- 更新後は既存の rustdsh プロセスを再起動してください。

Install/update:

```sh
curl -fsSL https://github.com/jimoto-no-llm/rustdsh/releases/latest/download/install.sh | bash -s -- --from-release
```

Windows では同リリースの `install.ps1 -FromRelease` を使用してください。
