## 0.3.0 — どのLinuxでも新規導入が通るようになった機能追加版

- **導入手順の修正**: Linux x86_64 では、musl 環境と glibc 2.39 未満（Ubuntu 22.04 / Debian 12 / RHEL 9 系）でも `--from-release` が成功するようになりました。glibc ビルドが起動しない場合は静的 musl ビルドへ自動で切り替え、動かないバイナリを残しません。
- ダウンロードしたバイナリは導入前に実際に起動を確認します。SHA256 が一致していても起動できない場合は musl を再取得し、それでも起動しなければ失敗として終了します。
- **エージェントツールの既定変更**: 委譲したエージェントツールが既定で通常のファイル読み書きを行えるようになりました。厳格なサンドボックスは `--share-file` / `features.agent_tool_sandbox` / `RDSH_SECURITY=1` のオプトインです。
- **機能スイッチ**: `rdsh features` で17個の機能を一覧でき、`rdsh features on|off <id>` で1つずつ切り替えられます。Discord RPC・更新確認・通知・サウンド通知・Compute・予算ガード・リリースプローブ・slim の各ヒントまで、ネイティブとプラグインの両方が同じスイッチに従います。未設定の項目は既定のままで、既存の挙動は変わりません。
- 追加機能: `rdsh compute`（opt-in の常駐 pure-compute worker）、Dashboard のブックマーク・鮮度表示・workspace 保存、Windows のスコープ付きトレイ、DSH 0.2.1-alpha.1 対応、オフラインの fault simulator。
- 安全性: 認証情報・設定の保存を原子的にし、Dashboard の POST に `Origin` を要求し、release タグは main 系譜と必須 CI の通過を確認してからビルドします。

## 更新前に確認

- 対応プラットフォームは Linux x86_64（glibc / musl）、macOS arm64・x86_64、Windows x86_64 です。macOS と Windows の導入手順は 0.2.0 から変更はありません。
- 会話とモデル応答は本家 DSH のままで、互換性は維持されます。DSH **0.2.0-rc.2** と **0.2.1-alpha.1** の両方を認識します。
- 移行作業は不要です。既存の `rdsh` は同じコマンドで上書き更新できます。Linux の glibc 2.39 未満では静的 musl ビルドが自動選択され、`--musl` で明示することもできます。
- 機能スイッチは `$DSH_HOME/rdsh.json` の `features` 節に保存されます。旧キー（`discord.enabled` / `extras.enable` / `beta.context_engine`）も引き続き有効で、`features.<id>` を指定した場合だけそちらが優先されます。
- 更新後は既存の rustdsh プロセスを再起動してください。

Install/update:

```sh
curl -fsSL https://github.com/jimoto-no-llm/rustdsh/releases/latest/download/install.sh | bash -s -- --from-release
```

Windows は同じ Release の `install.ps1 -FromRelease` を使用してください。
