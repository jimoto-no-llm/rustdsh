## 0.9.0 — デスクトップと Web UI の実用化、検索の選択肢、インストーラ修正

- **ローカル Web UI とその常時起動**: ブラウザからデスクトップと同じ会話・承認・質問を扱える Web UI を追加し、systemd ユーザーサービスとして常時起動できるようにしました。`rdsh desktop web-ui status|on|off`（`--json` 可）と `rdsh setup --web` の設定画面から状態を確認して切り替えられ、**既定は常に OFF** です。トークンと URL は所有者限定（0600）で、稼働中の URL を画面から開けます（#793、#796、#798）。
- **Markdown 描画・ツール行・推論の表示**: デスクトップアプリと Web UI が、返答を見出し・リスト・引用・コードブロック（言語ラベルとコピーボタン付き）として描画し、ツール行は進行・成功・失敗の状態色、推論行は既定で折りたたんで表示します。Web UI は DOM ノード構築のみ（`innerHTML` 不使用）で、外部 URL を読み込みません（#796）。
- **日本語入力（IME）と上流 dsh への追随**: デスクトップの IME 入力を `EntityInputHandler` 経由にし、Wayland の text-input-v3（fcitx5 など）から日本語を入力できます。起動時は PATH・ローカル導入・npm グローバルから `--version` に応答する最新の `dsh` を選び、`--check-host`（`--online` で公開版と比較）で使用中のランチャーとバージョンを確認できます。更新があると Web UI とデスクトップ GUI が「dsh X が利用可能」バッジで知らせます（#788、#793）。上流 DSH **0.2.1-rc.2** で動くことを実機で確認しました（#788）。
- **検索の選択肢とオンデマンド起動**: `search.dsh_search_provider` で委譲した DSH の `web_search` をローカルの SearXNG プロバイダーに固定でき、`rdsh search-web --auto-start` はループバックのエンドポイントが落ちていれば同梱の compose を docker / podman で起動して検索します。compose と設定はバイナリに埋め込むため、インストール済みの `rdsh` でも動作し、公開ポートは `SEARXNG_URL` に従います。`--provider ollama` は Ollama のホスト型 Web Search API を使い、CLI ヘルプと Web 検索ガイドから Tavily の公式クイックスタートも案内します（#789、#794、#795）。
- **初心者向けスターターセットの既定オン**: `PROFILE=web` と `PROFILE=desktop` で、翻訳・探索サブエージェント・通知音・Git パネル・視覚的な回答が最初から入ります。`rdsh desktop install` は追加プラグインも取得でき、`--no-intelligent-ui` で外せます。`headless` は従来どおり essential のみ、`ui-comfort` / `easy-work` / `compute` はオプトインのままです（#791）。
- **デスクトップの信頼性と安全性**: 所有者限定だったホストのキャッシュ・`host.log`・`webui.url` に加え、接続先をリテラルのループバック IP だけに限定し、ホストのキャッシュはアトミックに置き換え、`--stop-host` は記録した PID だけを止めるようにしました。拒否された cookie は捨てて次の候補へ進むため、古いキャッシュが `401` として現れません。Web UI で再接続時に完了した応答が消えなくなり、失敗時は理由を表示し、質問の選択と自由入力は再描画でも保持します（#784、#793、#797）。
- **プロバイダとその他の修正**: `rdsh provider add commandcode --discover` が Chat Completions を提供するモデルだけを登録するようになり、空の `RDSH_BENCH_MAX_OVERHEAD_MS` は設定エラーとして拒否され、デバイスの無効化は永続化を待ってから完了します（#781、#785、#787）。
- **依存ライセンスの検査**: `deny.toml` で許可ライセンスを固定し、dev 依存も含めて `cargo deny check licenses sources` を PR・`main` への push・週次で実行します。第三者ライセンスは [THIRD_PARTY_LICENSES.md](../THIRD_PARTY_LICENSES.md) にまとめました（#790）。
- **ドキュメント**: スクリーンショットのギャラリーを 0.8.0 向けに撮り直しました（3ステップのセットアップウィザード、ダッシュボードの簡易／詳細表示、GPUI デスクトップアプリ、CLI 画面、更新バッジ）（#792）。

## 更新前に確認

この版の更新前に知っておくこととして、素の VM で見つかったインストーラの2件の不具合は v0.9.0 で既に修正済みです。旧版のインストーラを使う場合は次の点に注意してください。

- **素の VM で見つかったインストーラの不具合は、この版で既に直っています**。1件目は、`rdsh doctor` の出力を `head` にパイプしていたため、パイプが早く閉じると Node.js の無いホストで EPIPE により panic して core dump を残していたものです（終了コード 134）。install.sh は出力を変数に取り込んで先頭12行に切る方式になり、パイプが戻ると回帰テストが落ちます。2件目は、シリアル接続や SSH のヘッドレス環境でブラウザのセットアップ画面が開けず、そのまま停止していたものです。`DISPLAY` または `WAYLAND_DISPLAY` がある場合だけ画面を開き、無ければ `ssh -L` の例と次の一手を表示して処理を続けます（#799）。
- 対応プラットフォームは Linux x86_64（glibc / musl）、macOS arm64・x86_64、Windows x86_64 で、0.8.0 から変わりません。配布アーカイブの構成も同じです。
- 会話とモデル応答は本家 DSH のままで、互換性は維持されます。デスクトップアプリはハーネスのクライアントプロトコルに従うため、**0.2.0-rc.2**、**0.2.1-alpha.2**、**0.2.1-rc.2** で動作を確認しています（セッション一覧・モデルカタログ・ライブ配信・プロンプトのストリーミング・cookie 接続）。特定ビルドだけを試すときは `RDSH_DESKTOP_DSH` と `RDSH_DESKTOP_NO_ATTACH=1` を使います。移行作業も `rdsh.json` の変更も不要です。
- **既定値が2つ変わりました**: Web/デスクトップのプロファイルで初心者向けスターターセットが既定で入り、Web UI の常時起動は既定で無効（オプトイン）です。前者は `--no-intelligent-ui` などで外せ、後者は設定画面か `rdsh desktop web-ui on` で有効にできます。
- **ネイティブ・デスクトップアプリは引き続き同梱されません**: 配布アーカイブには含まれず、`apps/rdsh-desktop` を Rust 1.85 以上でビルドしたソース実行のみです。Linux のウィンドウには GPU 対応の Wayland セッションが必要です。
- **セキュリティ**: デスクトップアプリがホストのキャッシュとログ、Web UI の URL を所有者限定（0700/0600）で作るようになり、トークンを含む URL が同じマシンの他ユーザーから読めなくなりました（#797）。既定の `0022` umask を使う共有環境では、0.8.0 までこれらが読める状態でした。
- **版の判定: minor**（`[Unreleased]` に `### Added`（利用者に見える追加）があり、前回タグ以降に feature 系ラベル付きの PR もあるため）。新機能として認識される変更が中心のため minor としました。
- **ライセンス検査が厳しくなりました**: dev 依存も許可ライセンスの対象になったため、コピーレフトな dev 依存を追加すると PR の `Rust dependency audit` が落ちます。
- ソースからビルドする場合は Rust 1.85 以上が必要です（配布バイナリの利用に Rust は不要）。
- 更新後は既存の rustdsh プロセスを再起動してください。

Install/update:

```sh
curl -fsSL https://github.com/jimoto-no-llm/rustdsh/releases/latest/download/install.sh | bash -s -- --from-release
```

Windows では同じ Release の `install.ps1 -FromRelease` を使用してください。

デスクトップアプリを使う場合（配布アーカイブには未収録）:

```sh
cd apps/rdsh-desktop
cargo run --release
```
