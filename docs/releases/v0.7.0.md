## 0.7.0 — Linux ネイティブパッケージと配布チャネルの拡充

- **Linux ネイティブパッケージ（`.deb` / `.rpm`）をリリースに添付**: `packaging/nfpm.yaml` から固定した nfpm v2.48.0 でビルドする `packages` CD ジョブを追加し、v0.7.0 では `rdsh_0.7.0_amd64.deb` と `rdsh-0.7.0-1.x86_64.rpm` を添付します。`sudo apt install ./rdsh_*.deb`（Debian / Ubuntu / WSL）と `sudo dnf install ./rdsh-*.rpm`（Fedora / RHEL / Rocky / AlmaLinux）で `/usr/bin/rdsh` に導入でき、Rust ツールチェーンも `install.sh` も不要です。各パッケージには `.sha256` サイドカーを付け、リリース検証は欠落・重複・名前違い・改ざんを拒否します（#730）。
- **`.deb` / `.rpm` に GPG 署名はありません**: 署名鍵も apt / dnf のリポジトリも公開していないため、両コマンドはダウンロードしたファイルをそのまま導入します。入手元の検証は同じリリースの `rdsh_0.7.0_amd64.deb.sha256` / `rdsh-0.7.0-1.x86_64.rpm.sha256` で行ってください。パッケージは CI ビルドの glibc に依存するため（`.deb` は `libc6`、`.rpm` は `glibc`）、CI より古い glibc のホストでは musl アーカイブか `install.sh` を選んでください。
- **Homebrew / Scoop / winget のマニフェストを追加**: `packaging/homebrew/rdsh.rb`（macOS の Apple Silicon と Intel）、`packaging/scoop/rdsh.json`（Windows x64）、`packaging/winget/` の3ファイル（version / installer / en-US locale）を追加しました。各ファイルは公開済みアーカイブの URL と SHA-256 を固定し、導入手順と更新手順は `packaging/README.md` と `docs/PACKAGE-MANAGERS.md` にあります。`scripts/update-packaging-manifests.py` が `release-digests.tsv` / `release-digests-windows.tsv` から固定値を再生成し、`--check` でずれを検出します。Homebrew はこのリポジトリでは tap を公開せず、winget は `microsoft/winget-pkgs` への提出が利用者側の手動ステップです（#728）。
- **リリース頻度と semver 判定の自動化**: `.github/workflows/release-cadence.yml` が毎日 22:40 UTC（JST 翌 07:40）に `main` を見て、`[Unreleased]` に変更があれば版を判定し、`Cargo.toml` / `Cargo.lock` の版上げ、CHANGELOG の日付入り繰り上げ、`docs/releases/vX.Y.Z.md` の雛形作成までを行って `release/vX.Y.Z-prep` を push し、準備 PR を開きます（Actions が PR を作れない設定では issue に次の一手を残します）。**このワークフローはタグを打ちません**（#727、#729）。
- **semver は既定 patch、利用者が気づく追加は minor**: `[Unreleased]` に `### Added` があるか、前回タグ以降に `feature` / `enhancement` / `breaking` ラベル付きの PR があれば minor、それ以外は patch です。`0.x` の破壊的変更は major ではなく minor で表現し、CHANGELOG とノートで明示します。各リリースで `[Unreleased]` を空にし、タグは必須チェックが緑の exact SHA に手で打ちます。**本版を minor とするのは、`[Unreleased]` の `### Added` が新しい配布チャネルという利用者に気づかれる追加だからです**（#727、#729）。
- **参照されていなかったプラグインテスト2件を CI で実行**: `ci.yml` のプラグイン契約テスト（`node --test`）に、どの実行経路からも参照されず無防備だった `plugins/rdsh-ui-comfort/test/logic.test.mjs` と `plugins/mcp-resource-artifacts/tests/source-patch.test.mjs` を追加しました（#725）。

## 更新前に確認

- 対応プラットフォームは Linux x86_64（glibc / musl）、macOS arm64・x86_64、Windows x86_64 です。`.deb` / `.rpm` は Linux x86_64 のみで、macOS / Windows はアーカイブと各パッケージマネージャのマニフェストを使います。
- 0.6.0 からの変更はパッケージング・CI・ドキュメント・リリースのダイジェスト台帳に限られ、`src/` の変更はありません。会話とモデル応答は本家 DSH のままで、互換性は維持されます（DSH **0.2.0-rc.2**、**0.2.1-alpha.1**、**0.2.1-alpha.3** のランタイムを認識）。
- 移行作業は不要です。`rdsh.json` の既存キーや既定値は変わりません。
- **配布チャネルは追加であって置き換えではありません**: `.deb` / `.rpm`、Homebrew、Scoop、winget は上級者向けの追加経路で、既定の `install.sh` / `install.ps1` は従来どおり使えます。各マニフェストは1つのリリースに固定されるため、v0.7.0 の公開とダイジェスト登録のあとに再生成します。
- **`.deb` / `.rpm` は無署名です**: apt / dnf のリポジトリ経由ではなくローカルファイルとして導入するため、GPG による配布元の検証はありません。SHA-256 サイドカーでの確認を推奨します。
- ソースからビルドする場合は Rust 1.85 以上が必要です（配布バイナリの利用に Rust は不要）。
- 更新後は既存の rustdsh プロセスを再起動してください。

Install/update:

```sh
curl -fsSL https://github.com/jimoto-no-llm/rustdsh/releases/latest/download/install.sh | bash -s -- --from-release
```

Windows では同じ Release の `install.ps1 -FromRelease` を使用してください。

Linux のネイティブパッケージを使う場合:

```sh
sudo apt install ./rdsh_0.7.0_amd64.deb      # Debian / Ubuntu / WSL
sudo dnf install ./rdsh-0.7.0-1.x86_64.rpm   # Fedora / RHEL / Rocky / AlmaLinux
```
