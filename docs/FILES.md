# 成果物ファイルの取得

`rdsh files` は、DSH セッションが `present` で宣言したファイルを一覧し、コピーして保存します。
セッションを指定しない場合は、保存済みトランスクリプトの更新日時が最も新しいものを使用します。

## CLI

```sh
rdsh files list --json
rdsh files list --session "session-id"
rdsh files get "/path/to/report.xlsx" --session "session-id" --out "/path/to/download/report.xlsx"
```

`--out` を省略すると、現在のディレクトリへ元のファイル名で保存します。
コピー先にファイルやシンボリックリンクが存在する場合は拒否します。
元ファイルと同じ場所を指定した場合も内容を保持し、別のコピー先を求めます。

`--force` は宣言チェックと通常の 512 MiB 上限を省略する、明示的なローカル操作です。
既存ファイルの上書きは許可しません。通常ファイル以外は取得できません。

現行 DSH の `sessions/<project>/<session-id>/session.v4.jsonl` と圧縮された
`.jsonl.zstd`、従来の JSON 形式に対応します。圧縮形式には `zstd` コマンドが必要です。
相対パスの成果物はセッションヘッダーの `cwd` を基準に解決し、作業ディレクトリが
分からない場合は拒否します。トランスクリプトの展開後のサイズ上限は 256 MiB です。
書き込み途中の最後の JSONL 行は読み飛ばしますが、完了済みの行の破損はエラーにします。

## HTTP

`rdsh serve` の認証済み API でも、同じセッションの宣言を使用します。

```text
GET /api/files?session=<session-id>
GET /api/file?path=<file-path>&session=<session-id>
```

クエリ値はそれぞれ URL エンコードしてください。`session` を省略した場合は CLI と同じく
最新のトランスクリプトを使用します。ダウンロードは宣言済みの通常ファイルに限り、
512 MiB 上限を適用します。HTTP 経由で `--force` 相当の操作はできません。

応答はファイルを丸ごとメモリに載せず、検証済みのファイルハンドルから検証時のサイズまで
送信します。途中でファイルが短くなった場合は不完全な応答として接続を閉じます。
送信には全体で 10 秒の期限を設け、読み取りを停止したクライアントが接続枠を占有し続ける
ことを防ぎます。保存名は日本語にも対応し、改行や引用符を HTTP ヘッダーとして解釈させません。
