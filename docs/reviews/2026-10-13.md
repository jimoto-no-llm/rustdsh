## 修正した指摘

| 優先度 | 発生条件と影響 | 修正 |
| --- | --- | --- |
| P1 | 更新用スナップショットが `dashboard/ui/` を含まず、固定された実行環境で `state.mjs` の import が失敗。更新・ロールバック関連の4テストが失敗 | `release-artifacts.mjs` で UI ディレクトリも収集。固定環境からの実 import と改変検出を追加検証 |
| P1 | 長すぎる ID や不正な観測メタデータを持つブロックを文字表示へ変換しても、不正値を保持。保存後の読み込み検証で拒否 | `ui/registry.mjs` と `ui/surface.mjs` で有効な ID とメタデータだけを保存。ID がない変換結果には一意な ID を発行 |
| P2 | 先行ブロックと同じ ID の操作付きブロックを受理し、クリック時に先行ブロックを検索して操作を見失う | ネストを含むブロック ID の重複を保存前・読み込み時に拒否 |
| P2 | `toString`・`constructor`・`__proto__` を許可リストのプロパティとして取得し、未知の操作を既知と判定 | `Object.hasOwn` による登録済みプロパティの確認 |
| P2 | `null` などの不正エントリーがブロック数に数えられず、201件の入力も受理 | 入力配列自体の件数も上限確認 |
| P2 | 生成された stdio 設定に保存先がなく、別環境のクライアントが既定の保存先で `runtime.json` を探して失敗 | `server.mjs` が `env.RDSH_DASHBOARD_HOME` の絶対パスも生成 |
| P2 | 開発者の `RDSH_ORIG_BIN` が回帰テストの legacy fixture より優先され、実際の dsh へ誤って委譲 | `tests/regress.sh` で両方の委譲先環境変数を解除し、各 fixture の明示設定を使用 |

UI の4つの回帰テストと、保存先を変えた stdio 接続テストは、修正前の失敗と
修正後の成功を確認しました。回帰スイートの環境依存は、環境変数を解除した
実行との比較で特定しています。

## Claude Code / Codex 利用者の導入

[MCP 導入ガイド](../MCP-CLIENTS.md)を新設し、日英 README と Dashboard README
の先頭側から案内します。Node.js の導入だけで、今のエージェントへ
タスク・質問・構造化 UI の表示を追加する経路です。
Linux/macOS/WSL と Windows の登録例、接続確認、再起動後の再接続、
複数クライアントでの ID と回答カーソルの扱いを記載しました。

設定形式は [Codex の公式資料](https://developers.openai.com/codex/mcp)、
[Claude Code の公式資料](https://code.claude.com/docs/en/mcp)と、ローカルの
`codex mcp add --help` / `claude mcp add --help` で照合しました。
ユーザーのクライアント設定や認証情報は変更していません。

`mcp-clients.test.mjs` は、生成された設定をそのまま使い、独立した2つの
stdio プロトコルクライアントから接続します。共有タスク、空白・日本語を含むパス、
保存先の変更、サーバー再起動後の接続鍵更新を実際の子プロセスで検証しました。
Claude Code／Codex 本体によるモデル実行の受け入れ試験とは区別します。
両 CLI のネイティブ start/resume/interrupt は引き続き未実装です。
