# 後続のiPhone「戻る」と完全URL起動

実施日: 2026-10-08。iPhone 15 / iOS 26.5 / Safari。WSLの合成Projectサーバーへ、Windows上のTailscale Serveと診断proxyを通して接続しました。Node v22.23.3。試験途中でサーバーを再起動せず、同じ認証情報を維持しました。

## 戻る操作

1. 完全URLをSafariへ貼り付けて質問一覧を表示。
2. Q-navigationに未送信の下書きを入力。
3. 同じSafariタブでabout:blankへ移動し、履歴の「戻る」で戻る。
4. 操作者が下書きの保持を確認。戻る後のconfig/stateは11:19:53 UTCに200、期待する接続情報と一致。
5. fixture最終記録（11:23:31.475 UTC）は回答POST0、転送0、保存0、全5問が未回答。意図しない送信なし。

この同じ1試行をproject-mobile-wsl-backとproject-mobile-tailscale-backの2セルから参照します。独立した2試行ではありません。tested_atは戻る後のAPI観測時刻で、ボタンを押した正確な秒は未取得です。下書きの保持は操作者の確認、件数と認証はメタデータ診断・fixture結果から照合しました。focus位置は測っていません。

## 完全URLの貼り付けとリンク

- 11:17:43 UTC: 完全URL貼り付けでfragmentあり・保存キーなしの状態からconfig/state200。
- 11:21:03 UTC: 同じサーバーの完全URLリンクをコピーせずタップ。操作者が質問一覧を確認。fragmentあり・保存キーなし、config/state200、期待する接続情報と一致。
- 保存された認証情報だけで成功した試験ではありません。
- 以前の失敗に、URLキーなし・無効な保存キー・401という直接条件が残っています。ただし、当時の操作順や、どの引き渡しでその状態になったかは特定していません。
- アプリ起動後に表示URLからキーを取り除くのは既存のapp.mjsの処理です。新しい完全URLで復旧することと、過去の個別操作を特定することを区別します。

## 残る限界

外付けキーボードを接続していないため、iPhoneでのTab・Enter・Escは未確認です。PCでのTab・Escとタッチ操作の成功を代用しません。通常Safariから別アプリ内ブラウザーへの全パターンの認証引き渡しを保証するものではありません。
