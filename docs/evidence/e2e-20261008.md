# Additional E2E verification, 2026-10-08

Verified on macOS 26.6.2 arm64, Apple M5 Max, Rust 1.99.0, Node 24.21.0,
Chrome 154, zstd 1.5.7. Native integration tests and the extended performance
runner are Rust/Cargo targets. Browser tests use the existing JavaScript UI stack.
All application data and simulated credentials used by tests are temporary
fixtures; existing user profiles and installed application configuration are preserved.

## Verified behavior

| Layer | Execution | Observation |
| --- | --- | --- |
| Rust unit + settings tests | `cargo test --release` | 66 unit + 3 settings tests passed |
| Native binary E2E | same Cargo command | 11 integration tests passed, 0 ignored |
| Rust performance oracle | `cargo test --release --example benchmark_extended` | 2 tests passed |
| Static validation | fmt + release Clippy, all targets, warnings denied | passed |
| Plugin and settings client | Node tests | 18 passed |
| Project dashboard | `npm test --prefix dashboard` | 8 passed |
| Existing CLI regressions | sandboxed `tests/regress.sh` | 42 checks passed |
| Real browser/server/MCP | `npm test --prefix tests/e2e` | 3 complete flows passed, no JS or console errors |
| Installed DSH settings plugin | optional `test:harness`, DSH 0.2.0-rc.2 | desktop settings flow passed; mobile readability failed |

The native test suite covers these paths:

- Known-size and concatenated zstd frames, first/warm cache behavior,
  growth, corrupt cache, and schema-less legacy cache invalidation.
- Single and parallel sessions with corrupt, partly corrupt, or missing compressed
  files. Partial estimates stay inexact on both first and subsequent reads.
- Unknown-size streaming logs: recent stale values stay inexact; `stale_secs=0`
  forces recomputation. Unix tests require a real zstd executable.
- Four concurrent CLI writers across eight waves, followed by correct output and
  parseable cache readback.
- Real setup HTTP server: malformed Extras cannot erase saved choices,
  authentication/origin checks, shutdown, restart as serve, tokens/prune and
  retained settings. Truncated and oversized HTTP input does not damage the server.
- CLI tokens, prune, JSONL compact, search below/above the 32-file threshold,
  logs, guard rules, and settings as a combined binary-level flow.
- Real loopback web-search responses: UTF-8 query encoding, URL prefix, result
  limit, entity handling and HTTP 503 rejection.

The 11 native tests run on Unix. Windows excludes the Unix-only dangling symlink
and streaming tests, leaving 9 native tests; platform CI results must be checked
at the updated PR head before acceptance.

## Browser flows and evidence

The browser test starts actual `rdsh setup --web`, `rdsh serve`, and the project
CLI. It uses the actual HTTP MCP client for task/question creation, a browser for
the answer, and independent API/file readback. It also verifies retained drafts
after an SSE update, persistence after process restart, and old-key rejection.
1280×900 and 390×844 viewports have no horizontal overflow. Screenshots show

The DSH plugin test saves a goal and a default port, confirms Extras survives,

## Before/after failures fixed

| Trigger | Before | After |
| --- | --- | --- |
| Growing unknown-size zstd with stale reuse | old value promoted to `tokens_exact:true` | stale value stays false; disabled stale window recomputes |
| Unreadable/partially missing compressed files | some first/cached/parallel totals reported exact | incomplete results stay inexact |
| Legacy cache without provenance | potentially stale cached value reused as exact | schema 2 required, old entries recomputed |
| Extras request has invalid type | saved choices silently cleared | HTTP 400; file unchanged |
| SearXNG responds HTTP 503 with parseable body | treated as successful search | nonzero exit with HTTP 503 error |
| Project browser requests favicon | spurious HTTP 401 console error | empty 204 asset response; APIs still require authorization |

Failures were reproduced before each fix and the covering native/dashboard tests
were rerun after it. Schema migration causes one recomputation of old session-token
caches. It does not change transcripts or settings.

## Remaining acceptance

Linux/macOS/Windows CI is tracked on [PR #177](https://github.com/sahenjp/rustdsh/pull/177).
This local evidence is not a substitute for the current-head CI result or merge.
The following remain unverified: Electron Desktop GUI startup, authenticated model
response/agent tool execution, Windows/WSL harness proxy, Tailscale sharing and
real-phone access, ChatGPT/native app integration, and long-running production load.
No existing provider credentials were imported or used. The upstream DSH mobile
settings layout remains a known readability failure.

[tests/e2e/README](../../tests/e2e/README.md) and
