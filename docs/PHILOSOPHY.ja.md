# 設計思想: Node.js と Rust の役割分担

`rdsh` は DeepSeek Harness を置き換えるものではありません。高速さが必要な処理を Rust で実装したランチャーです。
Node.js は得意な処理にそのまま使い、起動やチェックなど遅延を抑えたい処理だけを Rust で実装します。

この文書ではハイブリッド構成にした理由、Rust と Node.js の役割分担、対象外とした処理を説明します。
各サブシステムの役割は [ARCHITECTURE.md](ARCHITECTURE.md)、実測値は [BENCHMARKS.md](BENCHMARKS.md) にあります。

## Node.js に残す処理

Harness が多機能なのは、Node.js と V8 を基盤にしているためです。エージェントループ、プロファイル起動、
モデル接続、MCP ツール、Web UI はすべて上流の Node.js ランタイムが提供しています。これらを Rust で作り直すと、
上流の変更をすべて手作業で追いかけることになり、実装がずれた時点で互換性を失います。これらの処理は
ボトルネックではないため、Node.js に残します。

コストが問題になるのは、プロセスを起動するときと、小さな確認のたびにプロセスを起動し直すときです。
特に次の3点で起動コストが影響します。

## 起動コストが影響する3つの処理

1. **起動に時間とメモリがかかる。** Node.js を新しく起動すると、実際の処理に入る前にインタプリタを起動して
   モジュールを読み込みます。`dsh --version` は約88 ms、最大RSSは約66 MBです。1回のコマンドなら
   問題になりませんが、すべての呼び出しを仲介する CLI では、起動時間の違いが操作のたびに表れます。
2. **頻繁なフックはプロセス起動と相性が悪い。** PreToolUse フックはツール呼び出しごとに1回実行されます。
   そのたびに Node.js の判定プロセスを起動すると、起動コストがツール呼び出しの回数分だけ累積します。
   ポリシーを確認するためのフックがセッションで最大の固定コストになります。フックを無効にせず運用できる
   程度に、実行コストを抑える必要があります。
3. **外部ツールの実行には一括検査が必要。** モデルが実行を求めたコマンドは、1か所で検査し、拒否できるようにする
   必要があります（`rdsh guard`）。この処理はすべてのツール呼び出しで実行されるため、高速に動作し、
   監査できる程度に小さく実装しなければなりません。

## Rust で実装する処理

高速にする必要がある処理だけを Rust に移し、それ以外は Node.js に委譲します。遅延と安全性に関わる処理を
Rust で実装します。

- PreToolUse フック（`rdsh guard`）。オプトインの構造化ファイルポリシーを含みます。
- Node.js を起動する必要がないローカル処理。トークン見積り、検索、セッション一覧と圧縮、依存関係の検査、
  環境診断。

エージェントランタイム全体が必要な処理は Node.js に残し、dsh をそのまま `exec` で呼び出します。会話ループ、
プロファイル起動、モデル実行、MCP ツール、Web UI です。委譲先に渡す内容はバイト単位で同じため、
rdsh が dsh の動作を変えることはありません。変わるのは呼び出しにかかるコストだけです。

## アーキテクチャ

```text
            user / CLI
                |
                v
      +-------------------+          the reins
      |   rdsh  (Rust)    |          fast, memory-safe, auditable
      +---------+---------+
                |
     every tool call         local fast paths
                +-----------------------> guard, tokens, search, sessions
                |
                |  only when the work needs the full agent runtime
                v
      +-------------------+          the titan
      | DeepSeek Harness  |          session loop, models, MCP, Web UI
      | Core  (Node.js)   |
      +-------------------+
```

ローカル処理はツール呼び出しのたびに実行しますが、Node.js は起動しません。
エージェントランタイム全体が必要な場合だけ dsh を起動し、上流の実装をそのまま使います。

## 起動とフックのコスト（実測）

数値はすべて Linux x86_64 の1ホスト、`n=15` のプロセス単位の実測です。
[BENCHMARKS.md](BENCHMARKS.md) に記録があり、`scripts/benchmark-node-vs-rust.py`
（Node.js 側は `scripts/benchmark-node-reference.mjs`）で再測定できます。絶対値はホストに依存します。

| 処理 | rdsh (Rust) | Node.js の比較対象 | 差 |
| --- | --- | --- | --- |
| `rdsh --version` プロセス起動（起動のみ） | 約0.90 ms | 本家 `dsh --version` 約88 ms | 約98倍 |
| PreToolUse フック `rdsh guard`、1ツール呼び出し（起動込み） | 約2.0 ms | 等価な Node.js 判定スクリプト 76〜84 ms | 約40倍 |
| PreToolUse フックの最大RSS | 5.9 MiB | 49.6 MiB | 約1/8 |

注意点は2つあります。1つ目は、`約0.90 ms` が `rdsh --version` の**プロセス起動のみ**の値で、
フックの評価時間ではないことです。フックの値は起動時間を含みます。ツール呼び出し1回あたりのコストを
判断するときは、この値を使います。2つ目は、フック・`tokens`・`search` の比較対象が等価な
Node.js 実装であり、本家 `dsh` ではないことです。上流の dsh には該当するサブコマンドがないため、
これらの値で上流との倍率を主張することはありません。

プロファイルを起動したセッションはこの数値の対象外です。`rdsh` はプロファイル起動時に同じ上流 Node.js の
`dsh` を `exec` するため、会話の起動時間・対話速度・メモリは上流と同等です。

## Non-goals（やらないこと）

Rust に移す範囲は意図的に限定し、その方針を維持します。[ROADMAP.md](ROADMAP.md) の方針どおりです。

- エージェントループやプロファイル起動を Rust で再実装しない。
- Harness の UI やプロトコルを fork しない。
- Rust 自体を目的にしない。対象外の処理は Node.js と上流に残す。
