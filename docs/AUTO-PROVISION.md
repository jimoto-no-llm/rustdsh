# 初回の自動準備

`rdsh setup --web` から、実行環境の準備、モデルの選択、最初の会話まで進めます。
はじめて使う人は [SETUP.md](SETUP.md) の順番に進めてください。

## 実行環境

Unix のインストーラと Windows のインストーラは、不足する Node.js・pnpm・DSH を
利用者専用の `~/.local/share/rdsh/runtime/` に準備します。既存の利用可能な環境は再利用します。
Node.js は 24.22.1 の公式アーカイブを固定 SHA-256 で検証し、pnpm は 10.34.9、DSH は
0.2.2-alpha.3 を npm の公開レジストリから導入します。npm の install scripts は無効です。
管理者権限や、事前の pnpm・Corepack の導入は不要です。

本体だけを導入する場合は `install.sh --no-runtime` / `install.ps1 -NoRuntime`、
実行環境だけを準備する場合は `install.sh --runtime-only` / `install.ps1 -RuntimeOnly` を使います。
`RDSH_SKIP_RUNTIME=1` でも自動準備を省略できます。

Unix は Linux x64 / arm64、macOS x64 / arm64、Windows は x64 / arm64 の Node.js を扱います。
rdsh 本体の配布対象は従来どおりです。Linux musl 環境では公式 Node.js の glibc 要件を満たさない
場合があるため、自動準備が失敗したら適合する既存 Node.js を用意してください。

## クラウドのモデル

検出したログインを本人が接続するか API キーを登録すると、インストール済み会話エンジンの
モデルカタログと各プロファイルの設定から候補を表示します。既存の有効な既定モデルを優先し、
接続済みなら最初のモデルを自動選択します。モデル名を推測して登録しません。
設定するだけでは推論リクエストを送りません。アカウントの利用権限やキーの有効性は、最初の会話で確認します。

ChatGPT ログイン用の Codex CLI がなければ、画面の自動準備ボタンから利用者専用の場所へ
`@openai/codex@0.166.0` を導入し、公式 CLI のログイン画面を開きます。
ログインの完了は本人が行います。[公式 CLI の案内](https://learn.chatgpt.com/docs/codex/cli)も参照してください。

## ローカルのモデル

画面で `qwen3:1.7b`（約 1.4 GB）、`qwen3:4b`（約 2.5 GB）、`qwen3:8b`（約 5.2 GB）から選びます。
Ollama v0.40.14 の公式アーカイブを固定 SHA-256 で検証して展開し、選んだモデルを取得します。
モデル取得の成功と completion / tools 機能を確認してから、Web / TUI 用の初期モデルとして保存します。
初回はモデルに加えて数百 MB〜数 GB の実行環境も必要です。空き容量 12 GB 以上を目安にしてください。

rdsh 専用 Ollama は `127.0.0.1:11534`、モデル保存先は `~/.local/share/rdsh/runtime/models/` です。
通常の Ollama のポート・モデル保存先・設定は使いません。起動に必要な環境変数だけを渡します。
既存のプロファイルを編集せず、`first-model.json` と `first-model.yml` で起動時に適用します。
利用者が起動時に渡す `--patch` はその後に適用されます。Desktop アプリにはこの選択を適用しません。

## 進行状況と失敗時

準備はバックグラウンドで一つずつ実行され、取得量が分かれば進捗バーを表示します。
中止すると管理下の取得・展開プロセスを停止し、再試行ボタンでやり直せます。
モデルの取得済みレイヤーを再利用できるかは Ollama 側の状態によります。
チェックサムが違うアーカイブは展開しません。モデルの取得に失敗した場合、選択済みのモデルを変更しません。
準備中はセットアップの終了を受け付けません。サーバーを Ctrl-C で止めた場合も準備処理の中断を要求します。

HTTP API は localhost の Host / Origin とセットアップ用トークンを検証します。
ブラウザから実行するコマンド・URL・ファイルの場所を指定することはできません。
状態 API は固定のエラーコードを返し、子プロセスの出力や認証情報を返しません。

## 検証の範囲

Linux では隔離 HOME と Node.js / npm / pnpm / DSH のない PATH から実配布物を取得して確認します。
モデルの大容量ダウンロードは自動テストでは実行せず、HTTP ストリームの模擬サーバーで成功・中断・
不完全な応答・機能不足を確認します。Linux の手動検証では実配布 Ollama と qwen3:1.7b を取得し、短い応答まで確認しました。Windows の構文・起動確認は Windows CI で行います。
