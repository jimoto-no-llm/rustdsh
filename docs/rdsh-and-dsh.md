# dsh と rustdsh の関係、そして Web UI はどう変わるか

はじめて触る人向けの説明です。むずかしい言葉はできるだけ使わずに、
「何がどこで動いていて、rustdsh を入れると何が変わるのか」を順番に説明します。

## 1. 登場人物は2つだけ

| 名前 | 正体 | 役割 |
| --- | --- | --- |
| **dsh**（DeepSeek Harness） | Node.js で動く本体 | 会話・ツール実行・モデル接続など、実際の仕事をする |
| **rustdsh**（コマンド名は rdsh） | Rust で書かれたランチャーと道具箱 | dsh を速く安全に起動し、設定・更新・診断を手伝う |

たとえるなら、**dsh がエンジン**、**rustdsh がそのエンジンの操作盤と整備工具**です。
rustdsh は dsh を置き換えるものではなく、dsh を気持ちよく使うための周辺機器です。

## 2. Web UI はどちらも同じもの

ブラウザで開く画面（`http://127.0.0.1:3080`）は **dsh 自身の Web UI** です。
rustdsh を入れても、画面そのものが別物に変わるわけではありません。

rustdsh を入れると、この同じ画面に次のものが**追加**されます。

1. **設定タブ「rdsh」** — モデル・プロバイダ共有・Discord 表示・追加機能などをブラウザから変更できます（dsh 標準の設定画面に1タブ増えるイメージ）。
2. **更新のお知らせ** — rdsh 自身や dsh の新しい版が出たときに、画面上部に「更新があります」というカードが出ます（update / details / dismiss）。
3. **便利プラグイン** — 効果音の通知、Git 表示、モバイル向け表示など。
4. **自動更新** — 毎日決まった時刻に dsh の更新をチェックし、検証してから適用します（失敗したら元に戻します）。

つまり「**Web UI は dsh のまま、中身が少し賢くなる**」が正解です。

## 3. 何もわからない人のための開始手順

1. **インストール**（配布版のインストーラ、またはリポジトリの手順）
2. **初回セットアップ**: ターミナルで次を実行し、画面の案内に従って使うモデル（AI）と共有する設定を選びます。

   ~~~sh
   rdsh setup
   ~~~

   ブラウザで操作したいときは `rdsh setup --web` を使います。
3. **Web UI を起動**: ふだんは自動で起動します。手動で起動するときは次のとおりです。

   ~~~sh
   systemctl --user start dsh-web.service
   ~~~

4. **ブラウザで開く**: 起動時に自動で開きます。開かない場合は `~/.local/state/dsh-web/launch-url` の中の URL を開いてください。
5. **設定を変えたいとき**: 画面の設定 → タブ「rdsh」→ 変更したいカードを開いて保存。

## 4. よくある質問

**Q. rustdsh を入れると会話は消える？**
いいえ。会話は `~/.dsh` に保存されていて、dsh でも rustdsh 経由でも同じものを読みます。

**Q. 動作は速くなる？**
起動や診断・検索など「dsh の外側」の処理は Rust 実装で速くなります。会話そのものの速度は接続するモデル次第です。

**Q. 壊れたら？**
更新前に検証し、失敗したら自動で元に戻す仕組み（ロールバック）があります。

**Q. Web UI を使わずに済ませたい**
ネイティブのデスクトップアプリ（`apps/rdsh-desktop`）があり、同じ会話・承認・モデル切替をアプリの画面で操作できます。
